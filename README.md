# КТТО — сайт Кооперативного техникума Тамбовского облпотребсоюза

Сайт учебного заведения на **FastAPI + Jinja2 + SQLAlchemy (SQLite)** с личными кабинетами,
расписанием, журналом оценок и админ-панелью.

## Запуск

```powershell
cd C:\sergienko\project_stech_test_view
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

При старте создаются таблицы и заполняются демо-данные (группы, расписание, аккаунты,
оценки, документы). Повторный запуск данные не дублирует.

- Сайт: http://127.0.0.1:8000
- Админ-панель: http://127.0.0.1:8000/admin

## Структура

```
app/
  main.py        — маршруты, контентные страницы, админ-панель
  auth.py        — пароли (bcrypt), сессии, роли, контекст шаблонов
  models.py      — новости, пользователи, группы, расписание, оценки, ДЗ, документы
  seed.py        — демо-данные и лёгкие миграции для существующей БД
  data.py        — 8 специальностей: дисциплины, навыки, карьера, учебный план
  content.py     — тексты внутренних страниц (история, стипендии, общежитие и т.д.)
  templates/     — шаблоны (components/, info_page, account, teacher, documents, gallery)
  static/        — css (main, header, footer, page, account), js, фото и документы
```

## Роли и интерфейс

- **Гость** — полное меню: Главная, О нас, Поступление, Студентам, Контакты, Войти.
- **Студент** — меню из трёх пунктов: Главная, Дневник, Расписание + карточка пользователя.
- **Преподаватель** — Главная, Журнал, Расписание + карточка пользователя.
- **Администратор** — то же, плюс ссылка на админ-панель.

## Что где лежит

| Раздел | URL |
|---|---|
| Дневник студента | `/diary` |
| Расписание | `/schedule`, редактирование — `/teacher/schedule` |
| Журнал оценок | `/teacher/journal` |
| Документы (каталог) | `/documents` |
| Жизнь техникума (фото/видео) | `/gallery` |
| Специальности | `/specialties?item=<id>` |
| Поступление | `/admission` |

Документы загружаются через админ-панель (**Документы → добавить → поле «Файл документа»**),
файлы сохраняются в `app/static/docs/`.

## Примечания

- Пароли хранятся как bcrypt-хэши (passlib не используется из-за несовместимости
  с bcrypt 5.x; осталась поддержка проверки старых `$2b$`-хэшей и PBKDF2).
- В `seed.py` есть функция `_ensure_columns()`: она аккуратно добавляет недостающие
  колонки в уже существующую `sql_app.db`, поэтому база переживает обновления модели.
